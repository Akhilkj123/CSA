## Understand Log Management, Its Importance, and Approaches 
### Incident 
- A security incident is a single or a sequence of unexpected or undesired security events that can affect an organization’s security. It can be generated intentionally or unintentionally. It could involve the violation of security policies, acceptable use policies, or standard security practices.
### Event
- An event is an observed change in the day-to-day operations of a system, network, process, workflow, or person, like user signed into the system, router ACLs were updated, firewall policy was pushed, CPU utilization exceeded 99%, updating a database, etc. Security events are events that may affect the security of the system or network and indicate that there may be a violation of security policy or failing of any security safeguard.

### Log
- Logs are collections of information/data on events generated in the form of an audit trail by various components of an information system such as the network, applications, operating system (OS), service, etc. Logs serve as an indication that something may have gone wrong and help SOC analysts in analyzing and detecting the issues. Separately, transaction logs or firewall logs or intrusion prevention system (IPS)/intrusion detection system (IDS)
logs do not represent any fault.
#### Standard log formats
-  Syslog, Common Log Format (CLF), Extended Log Format (ELF), JavaScript Object Notation (JSON), Comma-Separated Values (CSV), Common Event Format (CEF),  W3C Extended Log File Format, Apache Log4j XML Format.
### Typical Log Sources
- A log source refers to a data source that builds an event log. Almost every device and application on the network has a logging capability and can produce a log to record the information regarding something that had occurred. Every security system generates logs in some or another forms. Windows logs, client and file server logs, router logs, firewall logs, and database logs are some of the examples of log sources in the network.
#### Push-based mechanism
- In this mechanism, the system or application sends records either on the local disk or over the network. If it is sent over the network, then there should be a log collector to collect the records. Syslog and Simple Network Management Protocol (SNMP) are the two main push-based protocols through which log records are transferred.
#### Pull-based mechanism
- In pull-based mechanism, a system or an application pulls the log records from a log source. It works on the basis of the client–server model. The system or device which follows this mechanism will store their log data in proprietary format.
### Need for Log 
- Logs are needed to understand lots of things occurring on the network from performance information to threat identification. They are a good source of forensic information that enables us to understand "What happened" after the occurrence of a security incident. Each log file comprises a variety of information, among which some may be invaluable.
#### System monitoring
- Logs provide detailed information about the transactions that are occurring across the environment.
#### Troubleshooting
- It can utilize different information and messages available in log files to troubleshoot a problem. However, these log files are not enough to troubleshoot the network problems. also have to utilize syslog for this purpose.
#### Compliance and Security
- In cybersecurity, logging is essential for compliance and security. Logs provide a detailed record of system activities, enabling organizations to adhere to regulatory standards like GDPR and HIPAA. They serve as a critical tool for detecting and investigating security incidents, identifying anomalies, and tracing breaches.
#### Forensics and analysis
- Logs play an important role in forensics and analysis processes. It is a permanent source of record that cannot be altered through normal course of actions. Logs are stored in chronological sequence, thus not only describing what happened but also when and how it happened.
#### Incident response
- Incident response activity requires proper correlation of log events across the number of devices and assets. This helps in determining the extent and impact of a network compromise and required steps for remediation.

### Logging Approaches
#### Local Logging 
- Local logging is the mechanism of logging user activities in the host machine. In other words, it is the process of writing logs into the files on local disks. This approach is used by those systems that have a limited number of hosts.

### Understand and Analyze Local Logging Practices: Windows, Linux, and Mac Logs
#### Local Logging: Windows Logs
- Windows event logging service collects events from multiple sources and keeps them in a single location known as Windows event log. The Windows event logs are files that act as a primary source of evidence for all occurrences on a Windows system. It contains logs on system, security, and application notifications that are monitored and analyzed by security administrators to detect issues in the system.

#### Windows Event Log File Internals
- The Windows event log files are, essentially, databases with the records related to the system, security, and applications. The databases related to the system are stored in a file named System.evtx, the databases related to security are stored in a file named Security.evtx, and the databases related to applications are stored in a file named Application.evtx. These all-Windows event log files are stored in C:\Windows\System32\winevt\Logs folder

### Windows Event Log: Types and Entries
- Windows Event Viewer is a tool that provides a quick overview of when, where, and how an event occurred. It provides detailed information about events, errors, warnings, and information messages that occurred under the user’s OS.
#### Application event logs 
- These are the events related to applications installed in the system. It includes informational events, warnings from the applications, and errors that appear in an application.
#### Security event logs
- These are the events related to Windows security. It includes log-on/log-off activities, resource access, and also the information based on the Windows system's audit policies. It is analyzed by the security administrators to identify attempted and/or successful unauthorized activities.
#### Setup event logs
- These are enterprise-focused events that include all actions that occurred during installation, for example, location of memory dump from bug checks
#### System event logs
- These are the events that are logged by the OS segments. It includes information about hardware changes, system changes, device drivers, and all machine-related activities, for example, failure of device driver.
#### Forwarded event logs
- These are the events that are received from other systems present on the same network.
#### Custom log
-  A custom log facilitates an application to change the size of the log or add ACLs without influencing the other applications.
